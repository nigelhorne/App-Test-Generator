Changes

The two most recent releases in full, then the version history. The distribution's Changes file is the authoritative record.

0.48 — 11 November 2026

Enhancements

  • Harnesses check what a call leaves behind. Every call is checked for changes to the caller's globals ($_, $/, $, and $;), for files left in the working directory and for leaked file descriptors. The last two have config keys, check_files and check_fds, for routines whose job is to write a file or hand a handle back.
  • Accessors are tested for damage to their object. A getter must not change the object it was given, and a getset must change nothing but its own property. Memoised values and lazy initialisation are not reported. The config key is check_accessors.
  • Unbuildable classes are skipped, not failed. When a constructor refuses — an abstract base class, for example — extract-schemas marks the class so that its routines are skipped.
  • A directory semantic. A parameter the routine tests with -d is given a real temporary directory instead of an invented string.

Bug fixes

  • Coverage-guided fuzzing now gets coverage. The fuzzer was reading the names of the coverage criteria rather than the counters, so every run was random-only. The program must be started under Devel::Cover. Dies on hashref inputs with properties are now recorded as bugs, and corpus files are UTF-8.
  • BenchmarkGenerator quotes and escapes every name and constructor value, so the generated script always compiles, and no longer dies on input: undef.
  • Extraction recognises accessors that guard on defined($arg), no longer takes a getter driven by %ENV for a getset, types a wrapping setter as any, gives a wrapper that forwards @_ the target's input schema, emits matches patterns as Regexp objects, and no longer types a return built from $1 as an integer.
  • Harnesses now pass scalar inputs to positional routines, compare numeric getset round trips with ==, and only assert that a wrong-typed argument dies when the routine's own validator enforces the type.
  • deploy-workflows ships the current workflow files again; the embedded copies had fallen behind.
  • Prerequisites. The modules a generated harness loads (Test::Most, Test::Returns, Test::LectroTest) are now runtime prerequisites.

0.47 — 7 October 2026

Enhancements

  • extract-schemas --function NAME (-F) — extracts everything, then deletes every schema except NAME.yml and limits the fuzz run and the summary table to that one routine. Built for isolating a single failure in the self-fuzz suite; if the name is not found, the available routine names are printed and the command exits 1.
  • A clearer self-fuzz summary. The end-of-run table now lists every processed routine, not only the ones that fuzzed successfully, with the module name, the routine and either a test count or a plain reason for skipping: internal helper, excluded from the fuzz list, instance method needing an object, mandatory object parameter without a can hint, or FAILED.

Documentation

  • Expanded the MUTANT_SKIP examples.

Bug fixes

  • $pkg was extracted as a parameter. The invocant filter only knew $self and $class, so $pkg in import(), $proto in older constructors and $klass were emitted as position-0 string parameters — giving modules that use use Module key => value a spurious pkg: {type: string} entry. All extraction loops, the POD/code agreement check and the inline body guard now share the full self|class|pkg|proto|klass set. Three regression tests cover it.

Upgrading

cpanm App::Test::Generator

Schemas are compatible across releases: a schema that works with 0.48 has worked since the transform syntax settled. Generated harnesses are regenerated by tooling, so a stale one is replaced rather than migrated. If you keep generated .t files in version control, regenerate them after upgrading — an older harness may not know about a type or a config key that the new version accepts.
