  370: 
  371: Prepare an isolated temporary workspace for a single mutant.
  372: 
  373: The entire C<lib_dir> tree is copied into the workspace so that all module

  724: =head1 COMMON PITFALLS
  725: 
  726: =over 4
  727: 
  728: =item Calling C<apply_mutant> before C<prepare_workspace>
  729: 
  730: C<apply_mutant> requires C<prepare_workspace> to have been called first. The
  731: workspace holds the isolated copy of C<lib/> that receives mutations.
  732: 
  733: =item Passing an absolute path as C<lib_dir>
  734: 
  735: C<lib_dir> must be a B<relative> path (e.g. C<lib>). An absolute path causes
  736: C<apply_mutant> to construct a doubled directory under the workspace and then
  737: fail to find the target file.
  738: 
  739: =item Checking C<< $mutator->{workspace} >> after the refactor
  740: 
  741: Internal workspace state is stored in C<_workspace>, C<_relative>, and
  742: C<_lib_basename> (note the underscore prefix). The original C<lib_dir> value
  743: is never overwritten. Old code that reads C<< $mutator->{workspace} >> or
  744: C<< $mutator->{relative} >> (without underscores) will not find these keys.
  745: 
  746: =item Forgetting that C<run_tests> drives C<prove> from C<$^X>
  747: 
  748: C<run_tests> resolves C<prove> from the same Perl binary used to run the script.
  749: If you shell out to C<prove> directly in your own integration code, make sure
  750: you are using the matching C<prove>.
  751: 
  752: =item C<generate_mutants> in list vs scalar context
  753: 
  754: C<generate_mutants> returns a flat list in list context and an arrayref in
  755: scalar context.  Assign to an arrayref (C<my $m = $mutator-E<gt>generate_mutants()>)
  756: to guarantee you always get a reference regardless of calling context.
  757: 
  758: =item Applying two mutants to one workspace
  759: 
  760: C<apply_mutant> changes the workspace file and leaves it changed. If you
  761: apply a second mutant without a new C<prepare_workspace> call, the file
  762: holds both mutations and your results are wrong.
  763: 
  764: =item Expecting C<run_tests> to test the workspace
  765: 
  766: C<run_tests> runs the tests against the project's own F<lib> directory.
  767: If you only call C<apply_mutant> and then C<run_tests>, the tests load the
  768: original code, every mutant "survives", and the kill rate is 0%.
  769: 
  770: =item An unknown C<mutation_level> is not an error
  771: 
  772: Only the exact text C<fast> turns on fast mode. Any other value, for
  773: example C<Fast> or C<quick>, is accepted silently and works like C<full>.
  774: 
  775: =item How C<undef> and other false values are handled
  776: 
  777: =over 4
  778: 
  779: =item * C<< file => undef >> makes C<new> croak with C<file required>.
  780: An empty string makes it croak with C<file not found>.
  781: 
  782: =item * C<lib_dir> and C<mutation_level> use their default when the value
  783: is C<undef>, an empty string or C<0>. You cannot have a library directory
  784: that is really named C<0>.
  785: 
  786: =item * C<apply_mutant(undef)> stops with a Perl error, after the
  787: workspace check.
  788: 
  789: =item * C<run_tests> returns an empty string for "failed". It never
  790: returns C<undef>.
  791: 
  792: =item * A mutant's C<line>, C<original> or C<description> may be C<undef>.
  793: Fast mode treats each missing value as an empty string when it looks for
  794: duplicates.
  795: 
  796: =back
  797: 
  798: =item Extra arguments to C<new> are ignored
  799: 
  800: A wrong spelling such as C<libdir> or C<level> is not reported. The
  801: default value is used and no warning is given.
  802: 
  803: =item Skip markers must be alone on their line
  804: 
  805: C<## MUTANT_SKIP_BEGIN> and C<## MUTANT_SKIP_END> are only seen when
  806: nothing else except spaces is on the same line. Markers cannot be nested.
  807: The two marker lines themselves are also skipped.
  808: 
  809: =back
  810: 
  811: =head1 ENCODING
  812: 
  813: =over 4
  814: 
  815: =item * The C<file> and C<lib_dir> arguments
  816: 
  817: Paths are passed to the operating system unchanged. ASCII paths always
  818: work. For non-ASCII directory or file names, pass the path as bytes in
  819: the encoding of your file system (normally UTF-8).
  820: 
  821: =item * Source file contents
  822: 
  823: The file to mutate is read and written by L<PPI> as raw bytes. UTF-8
  824: text, other non-ASCII text and emojis inside strings, comments and POD
  825: are copied to the mutated file byte for byte. They are not damaged and
  826: they do not need to be decoded first.
  827: 
  828: =item * Text returned by a mutant
  829: 
  830: C<< $mutant->original >>, C<< $mutant->description >> and
  831: C<< $mutant->line_content >> can contain pieces of your source code.
  832: These are byte strings. If the source is UTF-8 and you print them through
  833: a UTF-8 file handle, decode them first with
  834: C<Encode::decode('UTF-8', $text)>.
  835: 
  836: =item * Skip markers
  837: 
  838: The markers are ASCII. They are found correctly in a file of any
  839: ASCII-compatible encoding, including UTF-8.
  840: 
  841: =item * Error messages
  842: 
  843: Messages contain the file path exactly as you gave it.
  844: 
  845: =back
  846: 
  847: =head1 LIMITATIONS
  848: 
  849: =over 4
  850: 
  851: =item * Single strategy registry
  852: 
  853: The four built-in mutation strategies are hardcoded in C<new>. There is no
  854: plugin mechanism for registering additional strategies without subclassing.
  855: A future version should accept a C<strategies> arrayref argument.
  856: 
  857: =item * No parallelism
  858: 
  859: C<run_tests> is synchronous. For large test suites or large mutant sets,
  860: wall-clock time scales linearly. The in-place mutation strategy also
  861: serialises all mutants behind a single file lock.
  862: 
  863: =item * PPI re-parse per apply_mutant call
  864: 
  865: C<apply_mutant> re-parses the workspace copy of the target file for every
  866: mutant. For very large single-file modules the PPI parse time may dominate.
  867: 
  868: =item * apply_mutant does not restore on abnormal exit
  869: 
  870: If the process is killed between the write and restore in
  871: C<bin/test-generator-mutate>, the project file is left mutated.
  872: A C<git restore lib/...> recovers it.
  873: 
  874: =back

 1010: =head1 STATE DIAGRAM
 1011: 
 1012: The object has three states. The state says what has been prepared so far.
 1013: 
 1014:       new(file => undef) or new(file => missing file)
 1015:     +--------------------------------------------------+
 1016:     |  action: croak, no object                        |
 1017:     v                                                  |
 1018:   +-------------+                                      |
 1019:   |  NO OBJECT  |--------------------------------------+
 1020:   +-------------+
 1021:         |
 1022:         | new(file => existing file)
 1023:         | action: store file, lib_dir, mutation_level;
 1024:         |         build the four mutation strategies
 1025:         v
 1026:   +---------------------+  generate_mutants()
 1027:   |                     |-----------------------------------------+
 1028:   |     CONSTRUCTED     |  action: read file, set skip_lines,     |
 1029:   |  (no workspace yet) |  return the mutants (state stays same)  |
 1030:   |                     |<----------------------------------------+
 1031:   |                     |
 1032:   |                     |  run_tests()
 1033:   |                     |-----------------------------------------+
 1034:   |                     |  action: run 'prove -l t', return 1/''  |
 1035:   |                     |<----------------------------------------+
 1036:   |                     |
 1037:   |                     |  apply_mutant(m)
 1038:   |                     |-----------------------------------------+
 1039:   |                     |  action: croak 'Workspace not prepared' |
 1040:   |                     |<----------------------------------------+
 1041:   +---------------------+
 1042:         |
 1043:         | prepare_workspace()
 1044:         | action: make temp directory, copy lib_dir into it,
 1045:         |         remember workspace path and relative file path
 1046:         v
 1047:   +---------------------+  generate_mutants()   (as above)
 1048:   |                     |-----------------------------------------+
 1049:   |   WORKSPACE CLEAN   |<----------------------------------------+
 1050:   |  (copy is the same  |
 1051:   |   as the original)  |  run_tests()          (as above)
 1052:   |                     |-----------------------------------------+
 1053:   |                     |<----------------------------------------+
 1054:   |                     |
 1055:   |                     |  prepare_workspace()
 1056:   |                     |-----------------------------------------+
 1057:   |                     |  action: new directory, new clean copy  |
 1058:   |                     |<----------------------------------------+
 1059:   +---------------------+
 1060:         |            ^
 1061:         |            | prepare_workspace()
 1062:         |            | action: new directory, new clean copy;
 1063:         |            |         the mutated copy is left behind
 1064:         | apply_mutant(m)
 1065:         | action: rewrite the workspace copy of the file
 1066:         |         with one mutation
 1067:         v            |
 1068:   +---------------------+  apply_mutant(m2)
 1069:   |                     |-----------------------------------------+
 1070:   |  WORKSPACE MUTATED  |  action: a second mutation is added on  |
 1071:   |                     |  top of the first (usually a mistake)   |
 1072:   |                     |<----------------------------------------+
 1073:   |                     |
 1074:   |                     |  generate_mutants(), run_tests()
 1075:   |                     |-----------------------------------------+
 1076:   |                     |  action: as above, state stays the same |
 1077:   |                     |<----------------------------------------+
 1078:   +---------------------+
 1079: 
 1080:   From any state: when the program ends, every temporary workspace
 1081:   directory is deleted.
 1082: 
 1083: A call that croaks leaves the object in the state it was in. The
 1084: workspace file is only rewritten after the mutation has succeeded.
 1085: 
 1086: No method of this class changes the real project file.
