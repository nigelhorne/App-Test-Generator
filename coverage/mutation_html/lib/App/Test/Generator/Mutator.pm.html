  646: =head1 LIMITATIONS
  647: 
  648: =over 4
  649: 
  650: =item * Single strategy registry
  651: 
  652: The four built-in mutation strategies are hardcoded in C<new>. There is no
  653: plugin mechanism for registering additional strategies without subclassing.
  654: A future version should accept a C<strategies> arrayref argument.
  655: 
  656: =item * No parallelism
  657: 
  658: C<run_tests> is synchronous. For large test suites or large mutant sets,
  659: wall-clock time scales linearly. The in-place mutation strategy also
  660: serialises all mutants behind a single file lock.
  661: 
  662: =item * PPI re-parse per apply_mutant call
  663: 
  664: C<apply_mutant> re-parses the workspace copy of the target file for every
  665: mutant. For very large single-file modules the PPI parse time may dominate.
  666: 
  667: =item * apply_mutant does not restore on abnormal exit
  668: 
  669: If the process is killed between the write and restore in
  670: C<bin/test-generator-mutate>, the project file is left mutated.
  671: A C<git restore lib/...> recovers it.
  672: 
  673: =back
