  538: =item Transforms that omit the C<input> key
  539: 
  540: If a transform's hashref has no C<input> key, C<generate> falls back to the
  541: base schema C<input> spec for that variant.  This is intentional but may
  542: produce identical argument lists across variants if you forgot to add per-
  543: transform input overrides.
  544: 
  545: =item A transform C<input> replaces the base C<input>. It is not merged.
  546: 
  547: If the base C<input> has the parameters C<a> and C<b>, and a transform
  548: C<input> has only C<a>, then that variant is called with C<a> alone.
  549: C<b> is not copied from the base.  Repeat every parameter you need inside
  550: each transform.
  551: 
  552: =item Only plain data is allowed under C<new>
  553: 
  554: A value under C<new> can be a number, a string, C<undef>, an arrayref or
  555: a hashref, nested to any depth.  A code reference or an object makes
  556: C<generate> croak.
  557: 
  558: =item How C<undef> is handled
  559: 
  560: =over 4
  561: 
  562: =item * C<schema =E<gt> undef> makes C<new> croak with C<schema is required>.
  563: 
  564: =item * A C<module> or C<function> that is C<undef> makes C<generate> croak.
  565: 
  566: =item * A missing or C<undef> C<input> or C<transforms> key means "no
  567: parameters" or "no transforms".  This is safe.
  568: 
  569: =item * C<new =E<gt> undef> (C<new: ~> in YAML) still counts as "has a
  570: constructor".  The script calls C<< Module->new() >> with no arguments.
  571: 
  572: =item * An C<undef> value B<inside> C<new> is written as the Perl word C<undef>.
  573: 
  574: =item * A parameter whose specification is C<undef> is passed as the
  575: Perl word C<undef>.
  576: 
  577: =back
  578: 
  579: =item The text C<undef> means "no input"
  580: 
  581: Some ATG schema files contain C<input: undef>.  YAML reads this as the
  582: five-letter string C<"undef">.  C<generate> treats that string, and any
  583: other C<input> or C<transforms> value that is not a hashref, as "no
  584: parameters".  Inside a transform, C<input: undef> gives a call with no
  585: arguments; it does B<not> fall back to the base C<input>.
  586: 
  587: =item Names that are not plain words are quoted for you
  588: 
  589: Transform names, parameter names and the keys under C<new> can contain
  590: any characters.  They are quoted and escaped in the generated script when
  591: needed.  Only C<module> and C<function> must be valid Perl names.
  592: 
  593: =item Which text is written as a number
  594: 
  595: A string under C<new> is written without quotes only when it is a plain
  596: decimal number such as C<42>, C<-1.5> or C<2e10>.  Everything else,
  597: including C<'Inf'>, C<'NaN'> and C<' 12'>, is written as a quoted string.
  598: Be careful with a leading zero: C<'007'> is written as C<007>, which Perl
  599: reads as an octal number.
  600: 
  601: =back
  602: 
  603: =head1 ENCODING
  604: 
  605: =over 4
  606: 
  607: =item * C<module> and C<function>
  608: 
  609: Use ASCII letters, digits, underscores and C<::> only.  Non-ASCII letters
  610: may pass the name check, but the generated script has no C<use utf8> line,
  611: so Perl will not read such names correctly.
  612: 
  613: =item * Transform names, parameter names and string values under C<new>
  614: 
  615: Full UTF-8 text, including non-ASCII letters and emojis, is copied into
  616: the script unchanged.  This is safe only if you take two steps yourself:
  617: write the script through a UTF-8 file handle
  618: (C<< open my $fh, '>:encoding(UTF-8)', $path >>), and remember that the
  619: script has no C<use utf8> line, so the running benchmark sees the text as
  620: bytes, not as characters.  For a benchmark that needs real character
  621: strings, add C<use utf8;> to the generated file by hand.
  622: 
  623: =item * Sample argument values
  624: 
  625: These are always ASCII (C<42>, C<3.14>, C<'hello'>, C<[]>, C<{}>).
  626: The generator never invents non-ASCII test data.
  627: 
  628: =item * The return value of C<generate>
  629: 
  630: A Perl character string.  It is ASCII unless your schema put non-ASCII
  631: text into it as described above.
  632: 
  633: =back
  634: 
  635: =head1 LIMITATIONS
  636: 
  637: =over 4
  638: 
  639: =item Representative values are heuristic
  640: 
  641: C<_representative_value> picks a single value based on type and C<min>/C<max>
  642: constraints.  It does not guarantee the chosen value exercises any particular
  643: code path, and it does not use the schema's C<enum> or C<matches> keys.
  644: 
  645: =item No round-trip with C<extract-schemas>
  646: 
  647: The generator reads any conforming ATG YAML schema, but it does not verify
  648: that the schema accurately describes the actual function's signature.  If the
  649: schema is stale, the generated benchmark may pass wrong argument types.
  650: 
  651: =back

  725:
