   99: =head1 DESCRIPTION
  100: 
  101: Given an ATG YAML schema (as produced by C<extract-schemas> or written by hand),
  102: generates a self-contained Perl benchmark script using L<Benchmark/cmpthese>.
  103: 
  104: Each transform defined in the schema becomes one variant in the C<cmpthese> call,
  105: with representative input values derived from the transform's type and range
  106: constraints.  When no transforms are defined, a single C<'default'> variant is
  107: emitted using the base input specification.
  108: 
  109: A parameter with a C<position> is passed positionally, in position order; a
  110: parameter without one follows as a C<name =E<gt> value> pair, so a routine
  111: written as C<my ($first, %opts) = @_> is timed as C<first(5, option =E<gt> 42)>
  112: rather than with the option left out.  C<sample_max>, when present, caps the
  113: numeric value chosen for that parameter while C<max> stays the documented
  114: range: a work factor such as a PBKDF2 round count is timed at its default
  115: rather than at a maximum that takes minutes per call.
  116: 
  117: The generated script is a plain C<.pl> file suitable for running directly with
  118: C<perl>.  It is not a test file and has no dependency on any test framework.

  528: # --------------------------------------------------
  529: sub _hash_or_empty {
  530: 	my ($v) = @_;
  531: 	return ref($v) eq 'HASH' ? $v : {};
  532: }

  534: =head1 COMMON PITFALLS
  535: 
  536: =over 4
  537: 
  538: =item Schema missing C<module> or C<function>
  539: 
  540: C<generate> croaks immediately if either key is absent.  Always ensure the
  541: schema has been loaded from a valid ATG YAML file before calling C<generate>.
  542: 
  543: =item Expecting test-framework output
  544: 
  545: The generated script uses C<Benchmark::cmpthese> and prints timing results to
  546: STDOUT.  It is B<not> a test file and produces no TAP output.  Do not run it
  547: with C<prove>.
  548: 
  549: =item OOP schemas need a C<new:> key
  550: 
  551: If the function under benchmark is an instance method, the schema must have a
  552: C<new:> key (even if its value is an empty hashref C<{}>) so C<generate> emits
  553: a C<my $obj = Module->new(...)> constructor call before the C<cmpthese> block.
  554: Without it, the variant calls use C<Module::function(...)> form.
  555: 
  556: =item Transforms that omit the C<input> key
  557: 
  558: If a transform's hashref has no C<input> key, C<generate> falls back to the
  559: base schema C<input> spec for that variant.  This is intentional but may
  560: produce identical argument lists across variants if you forgot to add per-
  561: transform input overrides.
  562: 
  563: =item A transform C<input> replaces the base C<input>. It is not merged.
  564: 
  565: If the base C<input> has the parameters C<a> and C<b>, and a transform
  566: C<input> has only C<a>, then that variant is called with C<a> alone.
  567: C<b> is not copied from the base.  Repeat every parameter you need inside
  568: each transform.
  569: 
  570: =item Only plain data is allowed under C<new>
  571: 
  572: A value under C<new> can be a number, a string, C<undef>, an arrayref or
  573: a hashref, nested to any depth.  A code reference or an object makes
  574: C<generate> croak.
  575: 
  576: =item How C<undef> is handled
  577: 
  578: =over 4
  579: 
  580: =item * C<schema =E<gt> undef> makes C<new> croak with C<schema is required>.
  581: 
  582: =item * A C<module> or C<function> that is C<undef> makes C<generate> croak.
  583: 
  584: =item * A missing or C<undef> C<input> or C<transforms> key means "no
  585: parameters" or "no transforms".  This is safe.
  586: 
  587: =item * C<new =E<gt> undef> (C<new: ~> in YAML) still counts as "has a
  588: constructor".  The script calls C<< Module->new() >> with no arguments.
  589: 
  590: =item * An C<undef> value B<inside> C<new> is written as the Perl word C<undef>.
  591: 
  592: =item * A parameter whose specification is C<undef> is passed as the
  593: Perl word C<undef>.
  594: 
  595: =back
  596: 
  597: =item The text C<undef> means "no input"
  598: 
  599: Some ATG schema files contain C<input: undef>.  YAML reads this as the
  600: five-letter string C<"undef">.  C<generate> treats that string, and any
  601: other C<input> or C<transforms> value that is not a hashref, as "no
  602: parameters".  Inside a transform, C<input: undef> gives a call with no
  603: arguments; it does B<not> fall back to the base C<input>.
  604: 
  605: =item Names that are not plain words are quoted for you
  606: 
  607: Transform names, parameter names and the keys under C<new> can contain
  608: any characters.  They are quoted and escaped in the generated script when
  609: needed.  Only C<module> and C<function> must be valid Perl names.
  610: 
  611: =item Which text is written as a number
  612: 
  613: A string under C<new> is written without quotes only when it is a plain
  614: decimal number such as C<42>, C<-1.5> or C<2e10>.  Everything else,
  615: including C<'Inf'>, C<'NaN'> and C<' 12'>, is written as a quoted string.
  616: Be careful with a leading zero: C<'007'> is written as C<007>, which Perl
  617: reads as an octal number.
  618: 
  619: =back
  620: 
  621: =head1 ENCODING
  622: 
  623: =over 4
  624: 
  625: =item * C<module> and C<function>
  626: 
  627: Use ASCII letters, digits, underscores and C<::> only.  Non-ASCII letters
  628: may pass the name check, but the generated script has no C<use utf8> line,
  629: so Perl will not read such names correctly.
  630: 
  631: =item * Transform names, parameter names and string values under C<new>
  632: 
  633: Full UTF-8 text, including non-ASCII letters and emojis, is copied into
  634: the script unchanged.  This is safe only if you take two steps yourself:
  635: write the script through a UTF-8 file handle
  636: (C<< open my $fh, '>:encoding(UTF-8)', $path >>), and remember that the
  637: script has no C<use utf8> line, so the running benchmark sees the text as
  638: bytes, not as characters.  For a benchmark that needs real character
  639: strings, add C<use utf8;> to the generated file by hand.
  640: 
  641: =item * Sample argument values
  642: 
  643: These are always ASCII (C<42>, C<3.14>, C<'hello'>, C<[]>, C<{}>).
  644: The generator never invents non-ASCII test data.
  645: 
  646: =item * The return value of C<generate>
  647: 
  648: A Perl character string.  It is ASCII unless your schema put non-ASCII
  649: text into it as described above.
  650: 
  651: =back
  652: 
  653: =head1 LIMITATIONS
  654: 
  655: =over 4
  656: 
  657: =item Representative values are heuristic
  658: 
  659: C<_representative_value> picks a single value based on type and C<min>/C<max>
  660: constraints.  It does not guarantee the chosen value exercises any particular
  661: code path, and it does not use the schema's C<enum> or C<matches> keys.
  662: 
  663: =item No round-trip with C<extract-schemas>
  664: 
  665: The generator reads any conforming ATG YAML schema, but it does not verify
  666: that the schema accurately describes the actual function's signature.  If the
  667: schema is stale, the generated benchmark may pass wrong argument types.
  668: 
  669: =back
