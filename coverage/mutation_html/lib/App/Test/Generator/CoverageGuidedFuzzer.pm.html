  134: =head1 DESCRIPTION
  135: 
  136: Implements coverage-guided fuzzing on top of App::Test::Generator's
  137: existing schema-driven input generation. Instead of purely random
  138: generation it:
  139: 
  140: =over 4
  141: 
  142: =item 1. Generates or mutates a structured input
  143: 
  144: =item 2. Runs the target sub under Devel::Cover to capture branch hits

 1743: =head1 COMMON PITFALLS
 1744: 
 1745: =over 4
 1746: 
 1747: =item Forgetting that C<load_corpus> does not restore bugs
 1748: 
 1749: The JSON written by C<save_corpus> contains a C<bugs> array, but C<load_corpus>
 1750: reads only the C<corpus> key.  A freshly loaded fuzzer always starts with an
 1751: empty bugs list.  If you need to carry bugs across sessions, persist them
 1752: separately.
 1753: 
 1754: =item Assuming coverage guidance is always active
 1755: 
 1756: If C<Devel::Cover> is not installed, the fuzzer falls back to random-only mode
 1757: and emits a warning.  Corpus entries in this mode have C<coverage =E<gt> {}>
 1758: and are kept using the C<RANDOM_KEEP_RATIO> (20%) heuristic rather than branch
 1759: novelty.  Install C<Devel::Cover> (or C<cpanm --with-recommends
 1760: App::Test::Generator>) for full coverage-guided behaviour.
 1761: 
 1762: =item Using C<refaddr> on C<corpus()> after C<minimize_corpus>
 1763: 
 1764: C<minimize_corpus> replaces C<$self-E<gt>{corpus}> with a B<new> arrayref.
 1765: Any caller that holds a reference to the old arrayref (e.g. from a prior
 1766: C<corpus()> call) will see a stale snapshot.  Always call C<corpus()> after
 1767: C<minimize_corpus> if you need the current list.
 1768: 
 1769: =item Setting C<timeout =E<gt> 0> on blocking targets
 1770: 
 1771: Setting C<timeout> to 0 disables the per-call C<alarm()>.  This is correct for
 1772: targets that legitimately block (e.g. sleeping, waiting on I/O), but means a
 1773: hung target_sub will hang the whole fuzzing run indefinitely.  Use a
 1774: process-level timeout (e.g. C<Sys::AlarmCall>) if you need a safety net for
 1775: blocking code.
 1776: 
 1777: =item A C<timeout> below one second turns the timeout off
 1778: 
 1779: C<timeout> is passed to Perl's C<alarm>, which works in whole seconds.
 1780: A value such as C<0.5> becomes C<0>, and C<0> means "no timeout".
 1781: 
 1782: =item A schema without an C<input> key
 1783: 
 1784: The generator reads only C<< $schema->{input} >>.  If that key is missing,
 1785: every generated input is C<undef>, and C<target_sub> is called with
 1786: C<undef> each time.  No error is raised.
 1787: 
 1788:     schema => { name => { type => 'string' } }             # wrong
 1789:     schema => { input => { type => 'string' } }            # right
 1790: 
 1791: =item C<target_sub> always gets exactly one generated argument
 1792: 
 1793: C<input> describes B<one> value.  If C<input> is a list of named
 1794: parameters without a C<type> key of its own, one random string is
 1795: generated, not a hash.  To pass a hashref, describe it:
 1796: 
 1797:     input => {
 1798:         type       => 'hashref',
 1799:         properties => { age => { type => 'integer', min => 0 } },
 1800:     }
 1801: 
 1802: The C<position> and C<named> keys of an extracted schema describe a
 1803: multi-argument call that this fuzzer does not build.  A parameter map without
 1804: a C<type> of its own still yields the single string described above, so a
 1805: routine written as C<my ($first, %opts) = @_> receives it as C<$first> and the
 1806: trailing named options are left at their defaults.
 1807: 
 1808: =item How C<undef> and other false values are handled
 1809: 
 1810: =over 4
 1811: 
 1812: =item * C<schema> and C<target_sub> must be B<true> values, not only
 1813: defined.  An empty hashref C<{}> is true and is accepted.

 1827: An C<undef> value for a field marked C<optional> is valid.
 1828: 
 1829: =item * C<save_corpus(undef)> and C<load_corpus(undef)> croak with
 1830: C<path required>.
 1831: 
 1832: =back
 1833: 
 1834: =item Nested data is copied only one level deep
 1835: 
 1836: When a hashref or arrayref input is mutated, only the top level is copied.
 1837: Deeper hashes and arrays are shared between the old and the new corpus
 1838: entry.  If your C<target_sub> changes its argument in place, it can
 1839: silently change other corpus entries too.  Write C<target_sub> so that it
 1840: only reads its argument, or make it take a deep copy first.
 1841: 
 1842: =item C<load_corpus> adds entries. It does not merge or replace.
 1843: 
 1844: Loaded entries are put after the entries already in the corpus.  Nothing
 1845: is compared and nothing is overwritten.  Load a file twice and you have
 1846: two copies of each entry.
 1847: 
 1848: =item Every C<run> adds five more random seed inputs
 1849: 
 1850: The corpus grows by at least five entries per C<run> call.  Call
 1851: C<minimize_corpus> before C<save_corpus> if the object is used for many
 1852: runs.
 1853: 
 1854: =item Some warnings are recorded as bugs
 1855: 
 1856: A warning from C<target_sub> that contains the word C<uninitialized>,
 1857: C<undefined>, C<blessed> or C<invalid> is recorded as a bug, even though
 1858: the call did not die.  Warnings are caught during the call, so they are
 1859: not printed.  Other warnings are thrown away.
 1860: 
 1861: =item C<branches_covered> is 0
 1862: 
 1863: This means that no branch data was received.  Branch data is only
 1864: available when the whole program is started under C<Devel::Cover>, for
 1865: example with C<perl -MDevel::Cover script.pl>.  Having the module
 1866: installed is not enough.  Without it the run is random-only.  Do not read
 1867: a value of 0 as "the target has no branches".
 1868: 
 1869: =item Branch counts include more than your target
 1870: 
 1871: C<Devel::Cover> counts every branch in the program.  A few of the
 1872: branches counted in C<branches_covered> belong to the fuzzer and to other
 1873: modules, not to C<target_sub>.  Use the number to compare two runs, not
 1874: as an exact size.
 1875: 
 1876: =back

 1878: =head1 ENCODING
 1879: 
 1880: =over 4
 1881: 
 1882: =item * Inputs given to C<target_sub>
 1883: 
 1884: All strings are Perl character strings.  Strings made by the fuzzer use
 1885: ASCII letters, digits, space, tab, newline and the NUL character.
 1886: Mutation can also produce any character from 0 to 255.  The fuzzer never
 1887: invents characters above 255 (for example emojis) by itself.
 1888: 
 1889: =item * C<edge_case_array> and C<matches> in the schema
 1890: 
 1891: Full Unicode is supported, including non-ASCII letters and emojis.  Give
 1892: them as decoded character strings (C<use utf8> in your source, or a YAML
 1893: file loaded with L<YAML::XS>).  Such values are passed to C<target_sub>
 1894: unchanged and are mutated one character at a time.
 1895: 
 1896: =item * String C<min> and C<max>
 1897: 
 1898: Lengths are counted in characters, not bytes.
 1899: 
 1900: =item * C<save_corpus> and C<load_corpus>
 1901: 
 1902: Full Unicode is supported.  The file is written as UTF-8 JSON, and every
 1903: string, including non-ASCII letters and emojis, is loaded back exactly as
 1904: it was saved.  A corpus file written by version 0.47 or earlier, which
 1905: could hold Latin-1 bytes, is still read correctly.
 1906: 
 1907: =item * The C<path> argument
 1908: 
 1909: Passed to the operating system unchanged.  ASCII paths always work.
 1910: 
 1911: =item * Error text in C<bugs>
 1912: 
 1913: The C<error> value is whatever C<target_sub> died with, turned into a
 1914: string.  It is not encoded or decoded.
 1915: 
 1916: =back
 1917: 
 1918: =head1 LIMITATIONS
 1919: 
 1920: =over 4
 1921: 
 1922: =item Single-threaded
 1923: 
 1924: All fuzzing iterations run sequentially in the calling process.  For large
 1925: iteration counts, wall-clock time scales linearly.  Parallelism requires
 1926: splitting the iteration budget across multiple fuzzer instances and merging
 1927: their corpora.
 1928: 
 1929: =item Coverage granularity is branch-level
 1930: 
 1931: Branch coverage is the finest granularity Devel::Cover exposes via its public
 1932: API.  Path coverage (distinct sequences of branches) is not tracked.  Two
 1933: inputs that cover the same branches but exercise different call orders are
 1934: treated as equivalent.
 1935: 
 1936: =item No inter-run learning without save/load
 1937: 
 1938: The corpus is entirely in memory.  To carry learning across separate
 1939: invocations, call C<save_corpus> at the end and C<load_corpus> at the start of
 1940: each subsequent run.
 1941:

 2146:         |   action: add 5 random inputs, call target_sub
 2147:         |           'iterations' times, keep interesting inputs,
 2148:         |           record bugs, return the report
 2149:         | load_corpus(path)
 2150:         |   action: add the inputs from the file (no branch data)
 2151:         v
 2152:   +---------------------+  run()
 2153:   |                     |-----------------------------------------+
 2154:   |       GROWING       |  action: as above; corpus gets bigger,  |
 2155:   |  (corpus may hold   |  totals are added to the old totals     |
 2156:   |   copies and spare  |<----------------------------------------+
 2157:   |   entries)          |
 2158:   |                     |  load_corpus(path)
 2159:   |                     |-----------------------------------------+
 2160:   |                     |  action: add the file's inputs again    |
 2161:   |                     |<----------------------------------------+
 2162:   |                     |
 2163:   |                     |  save_corpus(path)
 2164:   |                     |-----------------------------------------+
 2165:   |                     |  action: write the file, no change      |
 2166:   |                     |<----------------------------------------+
 2167:   +---------------------+
 2168:         |            ^
 2169:         |            | run()  or  load_corpus(path)
 2170:         |            | action: as above
 2171:         | minimize_corpus()
 2172:         | action: replace the corpus with a new, smaller list;
 2173:         |         keep every covered branch and every bug input;
 2174:         |         return before / after / branches
 2175:         v            |
 2176:   +---------------------+  minimize_corpus()
 2177:   |                     |-----------------------------------------+
 2178:   |      MINIMIZED      |  action: nothing changes (before=after) |
 2179:   |  (no spare entries) |<----------------------------------------+
 2180:   |                     |
 2181:   |                     |  save_corpus(path)
 2182:   |                     |-----------------------------------------+
 2183:   |                     |  action: write the smallest file        |
 2184:   |                     |<----------------------------------------+
 2185:   +---------------------+
 2186: 
 2187:   In every state: corpus() and bugs() return the current lists and
 2188:   change nothing.  A call that croaks (bad path, unwritable file,
 2189:   unreadable file) changes nothing.

 2192:
